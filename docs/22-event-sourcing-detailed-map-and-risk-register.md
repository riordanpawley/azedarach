# Event Sourcing Detailed Map And Risk Register

## Purpose

This document expands the event-sourcing migration plan into a concrete work
map and risk register. It assumes the strategy from
[21-event-sourcing-migration-plan.md](21-event-sourcing-migration-plan.md):
prove the model through a session lifecycle/reconcile slice before broad
migration.

## Planning Principles

- Keep the daemon as the authority for durable intent and lifecycle decisions.
- Treat tmux, git, filesystem, hooks, and external providers as observation
  authorities.
- Make the event log the durable ordering module for accepted facts and
  observations.
- Keep projections as the only hot read path for CLI/TUI, orchestration, and
  invariant checks.
- Preserve the current stream/snapshot protocol until replacement semantics are
  explicitly accepted.
- Every migration slice must be reversible until its direct mutable path is
  removed.

## Detailed Workstreams

### W0: Vocabulary, Contract, And Ownership

Goal:

- define the domain language and durable event contract before implementation

Deliverables:

- event envelope contract in docs and tests
- event naming guide
- stream key guide
- retention class guide
- projection ownership matrix
- compatibility decision for protocol revisions vs event sequences

Key decisions:

- whether project event `sequence` becomes the protocol `revision`
- whether event IDs are generated by caller, daemon, or event log module
- whether mailbox JSONL is bridged, migrated, or left as an append-only adapter
  until the worker-evidence migration

Acceptance:

- event envelope tests prove deterministic JSON/MessagePack shape where exposed
- naming tests or lint reject command-shaped event names for durable facts
- docs name every current mutable store and its first migration phase

Rollback:

- docs/tests only; no runtime rollback required

### W1: Durable Event Log Module

Goal:

- add the append-only project event store with sequencing and idempotency

Likely files:

- `internal/daemon/events`
- `internal/daemon/events/migrations`
- `internal/contracts/protocol`
- daemon startup wiring

Deliverables:

- SQLite `daemon_events` table
- project-scoped sequence allocation
- unique event ID and command ID idempotency
- append batch API
- range read API
- stream-key read API
- event-log query-plan tests

Acceptance:

- concurrent append tests preserve strict per-project ordering
- duplicate command/event IDs return the original event or no-op result
- failed append transaction leaves no partial events
- independent projects do not block each other except at SQLite write-lock level
- query plans use event indexes for project sequence and stream-key reads

Rollback:

- event table can exist unused
- no command path depends on it yet

### W2: Projection Runtime

Goal:

- make projections explicit derived read models with offsets

Likely files:

- `internal/daemon/projections`
- `internal/daemon/state/projection_store.go`
- `internal/services/issues`

Deliverables:

- projection registry
- projection offset/checkpoint table
- projector transaction helper
- rebuild command or internal repair helper
- parity test harness for old path vs projected path

Acceptance:

- projector can start from empty projection tables and rebuild selected rows
- projection offset advances atomically with projection writes
- failed projection apply leaves offset unchanged
- projection rebuild is idempotent
- projection reads keep current query-plan guarantees

Rollback:

- leave projector unused and keep current mutable projection writes

### W3: Session Lifecycle Spike

Goal:

- prove the model on the hardest authority slice

Likely files:

- `internal/daemon/session_commands.go`
- `internal/daemon/runtime_reconcile.go`
- `internal/daemon/runtime_projection_writer.go`
- `internal/daemon/state/projection_store.go`
- `internal/daemon/testharness`

Events:

- `session.intent_recorded`
- `session.external_observed`
- `session.lifecycle_aligned`
- `session.projection_rebuilt`

Deliverables:

- dual-write session command events
- tmux reconcile observation events
- session projector for `daemon_session_projections`
- replay test that deletes and rebuilds session projection rows
- stream bridge preserves current `session.updated` / runtime projection events

Acceptance:

- start/stop/attach selected path appends intent events
- reconcile appends observation events before projection changes
- projection derived from events matches current direct projection state
- daemon restart rebuilds the selected projection from events before reconcile
- two daemon instances sharing a DB converge through event order
- current TUI/CLI stream behavior remains stable

Rollback:

- disable projector and keep direct session projection writer active
- event log remains audit-only for this slice

### W4: Projection-First Session Flip

Goal:

- make the selected session slice event-derived on the active path

Deliverables:

- direct projection writes removed for migrated session paths
- guard test catches bypasses
- repair command rebuilds session projection from event log
- runtime debug output shows projection offset and stale-observation age

Acceptance:

- direct mutation guard fails if migrated paths call projection store directly
- old direct write tests are either removed or rewritten around event/projector
  behavior
- stale-cache race tests pass from event-derived projection state

Rollback:

- feature flag or build-time config can re-enable direct projection writer for
  the migrated slice until cleanup is complete

### W5: Issue Graph And Worker Evidence

Goal:

- move orchestration-critical issue graph and worker evidence into the event
  model

Likely files:

- `internal/services/issues/client.go`
- `internal/daemon/task_commands.go`
- `internal/daemon/mail_commands.go`
- `internal/daemon/context_risk_commands.go`
- `internal/daemon/task_commands.go` orchestration/readiness paths

Events:

- `issue.created`
- `issue.details_changed`
- `issue.status_changed`
- `issue.dependency_added`
- `issue.dependency_removed`
- `worker.mail_recorded`
- `worker.evidence_recorded`
- `issue.closeout_checked`

Deliverables:

- issue and dependency projectors
- mailbox bridge from JSONL to events or event-backed mailbox store
- worker evidence projection for integration readiness
- context-risk projection fed by event-backed evidence

Acceptance:

- orchestration readiness explains decisions from event-derived graph/evidence
- closeout checks cite event IDs or event sequences for evidence
- mailbox legacy JSONL remains readable during migration
- worker integration does not require scanning both stores after bridge cutoff

Rollback:

- keep JSONL mailbox and existing issue tables as source while event log remains
  audit-only for worker evidence

### W6: Operations And Notices

Goal:

- event-source operation and notice lifecycle where ordering matters

Likely files:

- `internal/daemon/operation_runtime.go`
- `internal/daemon/operations/store`
- `internal/daemon/notices`
- `internal/tui/model_feedback_projection.go`

Events:

- `operation.submitted`
- `operation.state_changed`
- `operation.progress_recorded`
- `notice.recorded`
- `notice.lifecycle_changed`
- `notice.action_recorded`

Acceptance:

- stale operation failure cannot resurrect a resolved notice after replay
- operation progress retention keeps hot reads bounded
- notice list/get remains backed by projection reads
- terminal operation/notice cleanup writes compaction or retention events

Rollback:

- operation/notice tables remain source of truth until replay parity is proven

### W7: Specs, Decisions, Learnings

Goal:

- unify current audit logs with the shared event model

Likely files:

- `internal/services/issues/spec_store.go`
- `internal/services/issues/decision_store.go`
- `internal/services/issues/learning_store.go`
- `internal/daemon/decision_sync_md.go`

Events:

- `spec.requirement_changed`
- `spec.link_changed`
- `decision.recorded`
- `decision.link_changed`
- `learning.recorded`
- `learning.reviewed`
- `learning.promoted`

Acceptance:

- existing spec/decision audit log behavior remains queryable
- generated decision docs remain deterministic
- import/sync conflict behavior is unchanged or explicitly revised
- existing audit tables are either projections or formally deprecated

Rollback:

- keep specialized audit tables as projections fed by current store writes

### W8: Stream And Snapshot Semantics

Goal:

- decide how durable event sequence relates to client stream revision

Likely files:

- `internal/daemon/publish`
- `internal/contracts/protocol/stream.go`
- `internal/tui/model_update_loop.go`
- `internal/client/daemonclient`

Options:

- event sequence becomes protocol revision
- projection revision remains separate and references event sequence
- stream bridge emits projection revisions but carries source event IDs

Acceptance:

- revision gap behavior is still deterministic
- skipped telemetry remains safe to ignore only when annotated
- durable catch-up does not overload subscribers
- global stream preserves project isolation

Rollback:

- keep in-memory hub revisions as compatibility revisions while event log is
  used only for projection rebuild and audit

### W9: Cleanup And Enforcement

Goal:

- remove transitional dual-write paths only after evidence is strong

Deliverables:

- direct mutation import/dependency guards
- projection rebuild playbook
- event-log maintenance playbook
- migration status matrix in docs
- removal of feature flags for completed slices

Acceptance:

- no active entrypoint uses transitional adapters for completed slices
- boundary checks fail on direct projection writes from migrated paths
- restore/rebuild drill passes from a copied project DB

Rollback:

- cleanup is not started until rollback plans are no longer needed for the
  migrated slice

## Phase Gates

Each implementation phase must pass these gates before the next phase starts:

1. Contract gate: event names, payload schemas, stream keys, retention class, and
   projector target are documented.
2. Append gate: events are ordered, idempotent, and transactionally appended.
3. Projection gate: projection rebuild from events matches current read model.
4. Compatibility gate: existing CLI/TUI protocol behavior is unchanged.
5. Race gate: two-daemon stale-cache and concurrent append tests pass.
6. Recovery gate: projection table can be deleted and rebuilt.
7. Performance gate: hot reads use expected indexes and bounded replay.
8. Rollback gate: a direct rollback or disable path exists until cleanup.
9. Cleanup gate: direct mutation guards cover completed slices.

## Risk Register

| Risk | Failure Mode | Mitigation | Validation |
| --- | --- | --- | --- |
| Authority confusion | Old events are treated as live tmux/git/filesystem truth | Keep external systems as observation authorities; event payloads distinguish intent, observation, and projection facts | Reconcile tests prove stale observations do not satisfy live-presence invariants |
| Event taxonomy drift | Event names encode implementation details or commands | Event naming guide; schema tests; reject names like `row_updated` or `start_session_command` | Golden taxonomy tests and review checklist |
| Payload compatibility debt | Event payload fields change without upcasters | Version every event payload; require upcasters or append-only field additions | Round-trip tests across old fixtures |
| Event log write bottleneck | SQLite write lock stalls daemon operations | Batch append API; short transactions; project-scoped sequence allocator; keep heavy projection work outside append lock | Concurrent append benchmarks and lock-duration logs |
| Sequence gaps | Failed transaction reserves sequence and clients misinterpret gap | Allocate sequence inside commit transaction or record explicit skipped/void events | Transaction rollback test and stream gap tests |
| Duplicate command replay | Retried commands append duplicate domain events | Command ID idempotency table/index; return existing event result for duplicates | Duplicate command tests for each migrated handler |
| Non-idempotent projectors | Reapplying event mutates projection twice | Projectors are pure by event ID/sequence and track offsets transactionally | Apply same range twice and compare projection checksum |
| Projection drift | Dual-write mutable table and event-derived projection diverge | Parity tests and drift diagnostics during dual-write phases | Old-path vs event-projector comparison tests |
| Hidden direct writes | Migrated path bypasses event/projector module | Boundary guards and package import checks for migrated slices | `just check-boundaries` plus slice-specific depguard tests |
| Slow hot reads | CLI/TUI paths replay event history | Projections remain hot reads; no active UI path reads event history directly | Query-plan tests and TUI refresh benchmarks |
| Replay too slow | Full rebuild takes too long on large projects | Checkpoints; projection snapshots; bounded incremental replay | Large-project benchmark with seeded event volume |
| Telemetry flood | Git/activity/progress events bloat DB | Retention classes, compaction keys, latest-wins projection events, sampled telemetry for spike | Storage growth tests and compaction tests |
| Lost forensic data | Compaction deletes events needed for audit | Separate permanent domain history from compactable observations and ephemeral telemetry | Retention policy tests per event type |
| Privacy leak | Event payload stores full command args, file paths, or content unnecessarily | Payload minimization; redact long-form content and secrets; classify sensitive fields | Redaction tests and log/event payload review |
| Mailbox split brain | JSONL mailbox and event-backed mailbox disagree | Bridge JSONL through event importer with last imported seq; define cutoff point | Mixed-store mailbox replay tests |
| Decision/spec audit mismatch | Existing audit logs conflict with shared event log | Treat specialized audit tables as projections until migration decision is explicit | Sync/import tests compare audit and event timeline |
| Notice resurrection | Old failed operation event reactivates resolved notice | Include operation generation/source ordering in events; projector ignores stale terminal events | Replay stale failure after success test |
| Runtime resurrection | Replay recreates stopped sessions or deleted worktrees | Intent events do not perform side effects; reconcile observes live state before action | Restart/replay tests with missing tmux/worktree |
| Side effects during replay | Projector replay starts tmux or runs git commands | Projectors are side-effect free; side effects only from command/reconcile modules | Test projector with fake side-effect adapters that fail on use |
| Reconcile loop storm | Observation events trigger reconcile repeatedly | Reconcile dedupe keys, backoff, and stale age thresholds | Reconcile storm test with repeated identical observations |
| Cross-project bleed | Event sequence or projection reads mix projects | Project ID is required in every key and index; no defaulting inside event store append | Multi-project isolation tests |
| Global stream ordering ambiguity | Global subscribers see ambiguous interleaving across projects | Keep per-project sequence; global stream ordered by emitted time and project ID, or expose no global durable cursor | Global stream contract tests |
| Client revision breakage | TUI cursor semantics change unexpectedly | Stream bridge preserves current revision contract until accepted replacement | Existing stream cursor tests plus migration bridge tests |
| Subscriber overflow | Durable events lost from in-memory fanout under telemetry pressure | Durable event log is source for catch-up; telemetry remains skippable only when annotated | Overflow and catch-up tests |
| Snapshot mismatch | Snapshot revision and event sequence disagree | Snapshot payload includes projection offset/source sequence; validate before mutation | Apply revision gate tests with source sequence |
| Operation partial failure ambiguity | Batch apply records some events but response reports unclear state | Append per-operation result events in input order; partial success response references event IDs | Bulk apply partial failure tests |
| Migration half-state | Crash between event append and projection update | Projection offset transaction; repair command replays from last committed offset | Crash-injection tests around projector transaction |
| DB corruption | Event log table corrupted or partially unreadable | Backup before migrations; integrity check; export/import or rebuild from existing projections where possible | Recovery drill against copied DB |
| Backward migration impossible | New event-only state cannot be downgraded | Keep dual-write until downgrade window closes; document irreversible cutover points | Downgrade/rollback playbook test |
| Schema migration locks | Large migrations block active daemon | Small additive migrations; avoid table rewrites on hot path; run worktree-scoped validation first | Migration timing test on seeded DB |
| Poor module depth | Event modules expose table and sequencing details to callers | Keep append/read/project interfaces small; apply deletion test during review | Architecture review checklist |
| Too many seams too early | Hypothetical adapters add complexity without leverage | Add adapters only where dual-write or fake/replay adapter exists | Review: one adapter = temporary, two adapters = justified |
| Test fixture explosion | Every event path needs brittle fixtures | Build fixture helpers around event envelope and projector assertions | Fixture helper package and focused golden tests |
| Observability gap | Operators cannot diagnose projection lag or replay failures | Expose projection offsets, lag, last event, and last error in runtime debug | `runtime.reconcile` debug tests |
| Log cardinality | Event IDs and stream keys create noisy logs | Log wide events with bounded keys; avoid raw payload logs | Logging tests or review checklist |
| Disk growth | Event DB grows without bound | Retention classes, compaction jobs, vacuum guidance, and size metrics | Storage budget tests and maintenance command |
| Clock skew | `observed_at` order conflicts with sequence order | Sequence is ordering authority; timestamps are facts only | Tests sort by sequence for state, timestamp for display |
| Actor ambiguity | Events cannot explain human/agent/system source | Required actor/source fields from request metadata or daemon fallback | Event append validation tests |
| Causation loss | Timeline cannot link command, observation, projection, notice | Require causation/correlation IDs through command writer and projectors | End-to-end timeline test |
| Event version skew | Old daemon writes event schema new daemon cannot read | Handshake protocol remains separate; event upcasters support stored versions | Fixture tests with previous schema versions |
| Feature flag drift | Old and new paths behave differently for too long | Time-box dual-write phases; require cutover issue before more slices start | Migration status matrix reviewed before new slice |
| Rollback untested | Disable path exists but does not work | Rollback drill is part of phase acceptance | Worktree-scoped daemon rollback test |
| Human workflow confusion | Contributors do not know whether to edit events or projections | Docs and AGENTS updates after first active-path migration | Boundary docs and onboarding check |
| Over-migration | Low-value tables move to event sourcing only for uniformity | Require per-slice leverage test: causality, replay, race safety, or audit gain | Continue/stop decision after each slice |
| Under-migration | Event log remains audit-only and complexity persists | Each slice has explicit flip gate and cleanup gate | Migration matrix shows source of truth per slice |
| Security-sensitive replay | Replaying old events reintroduces unsafe actions | Replay is projection-only; side effects require fresh command authorization | Side-effect-free projector tests |
| Invariant regression | Projection-derived invariants evaluate stale state | Projection freshness barrier includes event offset and observation age | Invariant source tests with stale projection offset |
| External provider drift | Linear/GitHub/provider state changes outside daemon | Provider sync produces observation events with provider revision metadata | Provider sync replay tests when provider slices migrate |
| Large branch divergence | Long migration branch conflicts with active work | Implement as child slices; keep main branch integration frequent | Work graph uses independently reviewable child issues |

## Mitigation Work Items

These should be tracked as child issues before implementation starts:

1. Event taxonomy and schema-compatibility test harness.
2. Event log concurrency, idempotency, and transaction tests.
3. Projection offset/checkpoint transaction helper.
4. Session projection replay parity tests.
5. Reconcile observation freshness and stale-age debug output.
6. Stream bridge compatibility and overflow tests.
7. Query-plan and benchmark coverage for event reads and projection reads.
8. Retention/compaction policy for telemetry and operation progress.
9. Rollback and projection rebuild playbook.
10. Boundary guard for direct mutation bypasses after the first flip.

## Stop Conditions

Stop the migration and keep the projection-first model if the session slice shows
any of these:

- event/projector interfaces are as complex as the implementation they hide
- hot read paths become meaningfully slower even with projections
- dual-write drift is hard to detect or repair
- replay requires side effects to produce correct projections
- rollback cannot be proven in a copied worktree-scoped daemon
- the only benefit is audit history, with no gain in race safety, recovery,
  locality, or orchestration explainability

Continue only when the session slice proves better locality, clearer tests, and
stronger recovery than the current mutable projection path.
